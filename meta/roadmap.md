# 网站结构优化路线图

## 总目标

把 gonghejian.cn 从“个人博客”改造成“个人系统入口”。

不是展示“我有很多内容”，而是呈现“我正在构建一套面向 AI 时代的个人系统”。

## 第一阶段：建立骨架，不迁移发布文件

已建立：

- `content/articles/`：未来文章创作源、改写稿、编辑说明。
- `content/whitepapers/`：白皮书源稿和章节材料。
- `content/labs/`：实验室产品说明和原型文档。
- `skills/article-editor/`：文章改写和分发工作流。
- `meta/`：路线图、产品想法、官网改版简报、历史维护文档。

保留：

- `_posts/` 作为 Jekyll 文章发布目录。
- `whitepaper.md` 作为白皮书发布入口。
- `labs/`、`FA/`、`astrology/` 作为现有实验和产品页面。

## 第二阶段：收拢内部说明文档

目标：

- 根目录只保留真正的发布入口、构建入口和高频维护文件。
- 历史部署、预览、配置、排障说明移动到 `meta/archive/`。
- 新增规划文档放到 `meta/`，避免和网站 `/docs/` 文章入口混淆。

原则：

- 不影响现有页面 URL。
- 不移动 `_posts/`。
- 不把内部文档发布到线上网站。

## 第三阶段：重做首页和内容入口

首页目标：

- 个人身份定义页；
- 思想系统入口；
- 精选内容索引；
- 白皮书承接页；
- 未来产品与服务入口。

首页结构：

1. 首屏：弓箭 / 在 AI 时代，训练一种新的个人能力。
2. 现代职场人的四个风险。
3. 我正在构建的个人系统。
4. 精选记录。
5. AI 时代个人系统白皮书。
6. 实验室。
7. 关于弓箭。

导航：

首页 / 文章 / 白皮书 / 实验室 / 关于

## 第四阶段：设计内容生产流水线

推荐方向：

```text
content/articles/*.md -> _posts/YYYY-MM-DD-title.md
content/whitepapers/*.md -> whitepaper sections/pages
content/labs/*.md -> labs project brief
```

自动化前必须定义：

- front matter 标准；
- slug 规则；
- 标签规则；
- 精选记录规则；
- 白皮书引用规则；
- 自媒体分发摘要规则；
- 人工校对和回滚流程。

## 当前优先级

1. 稳定内部结构。
2. 统一官网定位和文案。
3. 改首页。
4. 继续改写文章，把旧内容纳入“个人系统”叙事。
5. 再做自动化发布流程。
