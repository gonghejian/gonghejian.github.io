# 弓箭网页设计系统

## 目标

把“高质量”变成可重复的判断与验收流程。先解决信息、任务和结构，再处理视觉。不要用更多卡片、渐变、阴影或字段掩盖产品判断不足。

## 开始前

1. 查看 `git status --short --branch`。
2. 阅读目标文件、相邻页面与全局样式。
3. 判断页面属于哪种类型，并读取 [页面类型](references/page-types.md)：
   - 品牌与内容入口；
   - 实验室工具；
   - 咨询型交付页面。
4. 阅读 [品牌系统](references/brand-system.md)。
5. 涉及组件实现时再读取 [组件规范](references/components.md)。
6. 完成前必须读取并执行 [质量门槛](references/quality-gate.md)。

## 强制工作流

### 1. 写清唯一任务

用一句话说明用户进入这一屏要完成什么。若一句话写不清，不进入视觉设计。

### 2. 做信息减法

把内容分为：

- 当前必须；
- 当前辅助；
- 按需展开；
- 应删除或移到下一步。

默认只显示当前必须项。用渐进披露保留复杂能力，不一次暴露全部信息。

### 3. 选择页面结构

先画信息层级和任务路径，再选择布局。不得因为仓库已有三栏、卡片或英雄区就机械复用。

### 4. 建立视觉方向

视觉方向必须同时回答：

- 这是什么类型的产品？
- 它应该让人感到什么？
- 哪些内容是视觉主角？
- 品牌如何出现而不干扰任务？

咨询型“高级感”来自严谨层级、编辑感、证据与节奏，不来自黑金、大渐变或装饰性数据。

### 5. 实现交互状态

至少实现 default、hover、focus-visible、active、disabled、loading 或 saved（适用时）。控件使用语义化 HTML，键盘可访问，主要点击目标不小于 44px。

### 6. 真实渲染验收

必须用浏览器或无头浏览器查看实际页面。至少检查：

- 1440px 桌面；
- 768px 窄屏或平板；
- 390px 手机；
- 有内容和空状态；
- 关键交互与弹层。

禁止只凭源码宣称视觉完成。

### 7. 技术验收

- 保持 Jekyll 可构建；
- 运行 `git diff --check`；
- 验证 DOM 引用和 JavaScript 语法；
- 不改变已发布 URL；
- 临时预览图不得随正式页面发布。

## 决策原则

- 内容优先于容器，任务优先于装饰。
- 一屏一个主任务，一个主行动。
- 将复杂度放到正确的步骤，不是假装复杂度不存在。
- 不把品牌页、工具页和咨询交付页做成同一套皮肤。
- 参考世界一流产品时，学习信息架构、比例、节奏和状态，不复制表面风格。
- Apple HIG 适合校准清晰度、层级、熟悉模式和可访问性。
- Material Design 适合校准自适应布局、组件状态和系统一致性。
- 咨询公司风格适合校准叙事、证据、编辑感和决策导向。

## 交付汇报

说明：

- 页面类型和唯一任务；
- 删除、隐藏或后移了哪些信息；
- 采用了什么结构和原因；
- 实际检查了哪些尺寸和状态；
- 是否影响发布、是否已推送与部署。
