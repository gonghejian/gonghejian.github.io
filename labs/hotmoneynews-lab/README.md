# 项目分析：SimCity, but with Permits

## 一、这是什么

一个把"城市建设模拟"和"真实行政审批流程"结合起来的恶搞/讽刺型网页小游戏：玩家像玩 SimCity 一样规划地块、盖楼，但每盖一个东西都要走一遍"许可证审批"——填表、等待、被驳回、再申诉。核心笑点在于把现实中令人抓狂的官僚流程游戏化。

## 二、它怎么赚钱？

先说结论：**这类 Show HN 小项目大概率本身不赚钱，它的价值在流量和作品集，不在营收。** 但可以拆出几条现实路径：

- **广告/赞助变现（最现实）**
  - 页面挂 Google AdSense 或 Carbon Ads（开发者向流量单价较高）。
  - 找 SaaS 工具（如合规、审批、建筑软件）做赞助位。
- **流量导流变现**
  - 作为个人作品集/引流入口，导向作者的咨询、课程、付费产品。
  - 收集邮件列表，后续卖"独立开发者/产品"相关内容。
- **付费解锁/买断**
  - 免费玩基础关卡，付费解锁"沙盒模式""跳过审批作弊码""更多城市地图"。
  - 一次性买断（如 $3–5）或 Patreon 式赞助。
- **B2B 定制（天花板最高但最难）**
  - 把"审批流程游戏化"做成培训工具，卖给政府/建筑/合规培训机构做"流程科普"或"压力测试"。
  - 这是唯一可能做成真生意的方向，但需要销售能力和行业资源。
- **IP/周边/梗传播**
  - 靠病毒传播积累品牌，做周边或联名（概率低，别指望）。

**关键判断：** 它的商业模式本质是"注意力生意"，不是"产品生意"。想靠它直接赚钱很难，想靠它**获得曝光、验证创意、积累作品集**则非常划算。

## 三、普通人如何低成本模仿

核心思路：**抓住"把枯燥流程游戏化"这个公式，换一个你熟悉的痛点场景，用最轻的技术栈做出来。**

- **选痛点场景（最重要）**
  - 找一个人人都骂、流程冗长、规则荒诞的领域：报税、签证、医院挂号、报销、公司请假审批、快递清关、学校选课……
  - 公式 = 熟悉的游戏机制（模拟经营/闯关/放置）+ 真实世界的荒诞流程。
- **技术栈压到最低**
  - 纯前端：HTML + JS（或 React/Vite），用 Canvas 或简单 DOM 网格做"地图"。
  - 不需要后端、不需要登录、不需要数据库——存档用 localStorage。
  - 美术用 emoji、色块、开源素材（Kenney.nl 免费游戏素材），别做美术。
- **MVP 只做一件事**
  - 一个场景、一个核心循环（点地块 → 填表 → 随机驳回 → 重试 → 通过）。
  - 2–3 天内做完能玩的最小版本，先发出去看反应。
- **把"荒诞"做成核心笑点**
  - 审批文案写真实又离谱的驳回理由（"缺少第 7 号附件""请重新提交已提交的文件"）。
  - 加随机事件、隐藏彩蛋、成就系统，提升传播性。
- **冷启动与传播**
  - 发 Hacker News（Show HN）、Reddit（r/InternetIsBeautiful、r/webgames）、V2EX、即刻、小红书"打工人共鸣"话题。
  - 标题用"XX，但是要审批/走流程"的句式，天然有梗。
  - 做一张能截图的"离谱驳回"画面，方便传播。
- **验证后再加码**
  - 有流量再考虑加关卡、加广告、做付费版；没流量就快速换下一个场景，别恋战。
- **避坑**
  - 别一上来做 3D、别做多人、别做账号系统——这些都会拖死你。
  - 别指望它赚钱，把它当"低成本获客/作品集/创意实验"。

## 四、一句话总结

**这是一个"注意力产品"而非"营收产品"；模仿它的正确姿势不是抄它的审批梗，而是抄它的公式——把一个人人痛恨的真实流程，用最轻的技术做成能截图传播的小游戏，2 天出 MVP，发出去验证，再决定加码还是换场景。**
