# 项目分析：HN.watch

## 一、这个项目是什么

HN.watch 把 Hacker News 上的帖子（标题+链接内容）自动转成**视频**，让用户不用读文字，直接看/听视频版 HN 内容。本质是**内容聚合 + AI 视频生成**。

---

## 二、它怎么赚钱？

坦白说，这类项目**直接赚钱很难**，但有几条现实路径：

- **广告/赞助**：视频前贴片或页面展示位，卖给开发者工具、SaaS、招聘方（HN 受众精准，CPM 不低）
- **付费订阅**：去广告 + 高清 + 离线下载 + 自定义频道（比如只看 "Show HN" 或 "Ask HN"）
- **联盟营销**：视频里提到的产品/工具挂 affiliate 链接（HN 帖子经常讨论新工具，转化天然）
- **B2B 授权**：把"文字转视频"的 pipeline 卖给媒体、播客、newsletter 作者
- **流量套利**：YouTube/TikTok 分发，靠平台广告分成
- **数据服务**：HN 趋势分析、话题热度榜，卖给 VC 或市场研究

**现实判断**：单靠这个站很难养活自己。真正值钱的是**自动化视频生成 pipeline**，可以复用到其他垂直内容源。

---

## 三、普通人如何低成本模仿？

### 核心思路
不要做"HN 视频版"，做**某个垂直领域的文字转视频**，竞争小、受众明确。

### 可执行步骤

- **选源**：挑一个高质量文字源，比如
  - 某 subreddit（r/programming、r/startups）
  - 某 newsletter（Lenny's Newsletter、Stratechery）
  - 某行业论坛/博客 RSS
  - 某 Twitter/X 账号的 thread

- **技术栈（全免费/极低成本）**
  - 抓取：`feedparser` / `requests` + RSS，或 `yt-dlp` 抓视频源
  - 摘要：用免费额度的 LLM API（Gemini Flash、Groq、DeepSeek）
  - 配音：Edge TTS（免费）或 ElevenLabs 免费额度
  - 画面：`moviepy` / `ffmpeg` + 简单模板（标题卡+字幕+背景图）
  - 字幕：`whisper.cpp` 本地跑，或直接 TTS 时同步生成
  - 托管：Cloudflare Pages / Vercel 免费层
  - 分发：YouTube + TikTok + 小红书/B站（中文场景）

- **成本控制**
  - 全部本地跑，月成本 < $5（电费+域名）
  - 用 GitHub Actions 定时任务，免费额度足够每天生成几条
  - 视频模板固定，只换文字和配音，边际成本趋近于零

- **冷启动**
  - 先手动做 10 条，发到目标社区测试反馈
  - 找到"哪类内容视频化后完播率高"，再自动化
  - 不要一上来就全自动，先验证需求

- **变现前置**
  - 从第一天就挂 newsletter 订阅入口（积累私域）
  - 视频描述放 affiliate 链接
  - 粉丝过千后接赞助

### 关键提醒

- **版权风险**：直接搬运他人内容做视频，可能侵权。优先选 CC 协议源，或做"评论/解读"而非"朗读"
- **平台风险**：纯 AI 生成内容在 YouTube 可能被限流，加真人出镜或独特剪辑能规避
- **差异化**：HN.watch 的弱点是"只是朗读"，你可以做**观点解读、对比分析、中文翻译**，价值更高

---

## 四、一句话总结

HN.watch 本身不是好生意，但它验证了**"文字源 → 自动视频"的 pipeline 可复用**。普通人应该抄的是**方法**，不是**选题**——选一个你懂的垂直领域，用免费工具搭 pipeline，先手动验证再自动化，靠分发和私域变现。

## 二、普通人如何低成本模仿？

**核心思路：不要做 HN 客户端，要做"某个垂直社区 + TUI/CLI"的组合。**

### 1. 选赛道（1天）

- 找**有 API、有活跃社区、但没人做终端工具**的平台：
  - V2EX、少数派、Product Hunt、Indie Hackers、Lobsters、GitHub Trending
  - 或者：掘金、SegmentFault、知乎热榜（需爬虫）
- 判断标准：**用户是开发者/极客 + 内容更新频繁 + 官方有 API 或 RSS**。

### 2. 技术选型（1天）

- **语言**：Go（编译单文件、跨平台）或 Rust（性能 + 装逼）。
- **TUI 框架**：
  - Go：`bubbletea` + `lipgloss`（Charm 出品，生态最成熟）
  - Rust：`ratatui`
  - Python：`textual`（上手最快，但分发麻烦）
- **不要从零写**：直接 fork 一个同类项目改，比如 `hntui` 本身就是很好的起点。

### 3. 最小可行版本（3-7天）

- 只做 3 个功能：**列表 + 详情 + 打开链接**。
- 数据源用官方 API 或 RSS，不要自己爬。
- 缓存到本地 SQLite，避免频繁请求。
- 加一个"已读/未读"标记，这是刚需。

### 4. 分发与冷启动（持续）

- **GitHub**：README 写清楚，放 GIF 演示（用 `vhs` 或 `asciinema` 录制）。
- **发帖渠道**：
  - HN 的 Show HN（如果做的是英文社区工具）
  - V2EX 的"分享创造"节点
  - Reddit 的 r/commandline、r/golang
  - 少数派、即刻、Twitter/X
- **蹭热点**：标题写"我用 Go 写了一个 XX 的终端客户端，比官方 App 快 10 倍"。

### 5. 成本控制

- **时间**：周末 2 天出 MVP，之后每周迭代 2-3 小时。
- **金钱**：¥0。GitHub 免费托管，域名可不买，用 `github.io`。
- **不要做的事**：
  - 不要做 UI 设计（TUI 没 UI）
  - 不要做用户系统（本地工具不需要登录）
  - 不要做多平台适配（先支持 macOS/Linux，Windows 用户自己想办法）

### 6. 变现前置（可选）

- 在 README 里放"赞助"链接和"付费版"预告。
- 付费版功能：AI 摘要、多账号同步、自定义主题、移动端同步。
- 用 Gumroad 或 Lemon Squeezy 收款，零成本起步。

# PaperMono 项目分析

## 一、它怎么赚钱？

先说结论：**这个项目本身几乎不赚钱，它的价值在于"验证需求 + 引流 + 卖硬件套件"。**

- **开源硬件 + 教程引流**：GitHub 开源代码本身免费，但作者可以通过 README 里的购买链接、博客广告、YouTube 教程流量变现。
- **卖成品/套件**：把 e-ink 屏 + ESP32 + 磁吸外壳打包成"开箱即用"套件，定价 $40–80，成本约 $15–30，毛利 50%+。
- **卖"懒人版"**：普通人不会焊接、不会刷固件，愿意多花 $20 买预装好的成品。
- **订阅/云同步（进阶）**：如果做多设备同步、家庭共享清单，可以收 $2–5/月。
- **内容变现**：写"我如何用 e-ink 做冰箱贴"的教程，挂联盟链接（Adafruit、Amazon）。
- **B端定制**：餐厅、诊所、仓库的"电子标签"需求，单价可到 $100+。

**核心逻辑**：开源代码是获客钩子，硬件套件和成品才是利润来源。这是典型的"Open Core + Hardware"模式。

## 二、普通人如何低成本模仿？

### 1. 最小可行版本（MVP）—— 先别碰硬件

- **用现成 App 验证需求**：先做一个手机网页版购物清单（PWA），能添加到主屏幕，模拟"冰箱贴"体验。
- **成本**：$0（用 Vercel + Supabase 免费额度）。
- **目的**：确认家人真的会用、会每天看。如果手机版都没人用，e-ink 版更没戏。

### 2. 硬件选型——抄作业，别自研

- **屏幕**：Waveshare 2.13" 或 2.9" e-ink 模块（约 ¥80–150）。
- **主控**：ESP32-C3 或 ESP8266（约 ¥15–30）。
- **外壳**：3D 打印或亚克力板 + 磁吸贴（¥10–20）。
- **电池**：18650 或 LiPo（¥15）。
- **总成本**：**¥150–250/台**。
- **关键**：直接 fork 作者的代码，改 WiFi 配置和 API 地址即可，别从零写。

### 3. 软件——用最懒的方式

- **后端**：直接用 Google Sheets 当数据库（Apps Script 做 API），或 Supabase 免费版。
- **前端**：手机网页用 Next.js + Tailwind，部署到 Vercel。
- **同步逻辑**：手机改清单 → 写数据库 → e-ink 每 5 分钟轮询一次。
- **省电技巧**：e-ink 只在内容变化时刷新，其余时间深度睡眠，一节电池能用 3–6 个月。

### 4. 生产与销售——先预售再备货

- **第一步**：在闲鱼/小红书发"自制 e-ink 冰箱贴"帖子，收 10 个意向客户。
- **第二步**：收 50% 定金，再去淘宝买元件，避免库存积压。
- **第三步**：第一批只做 5–10 台，手工焊接，验证良率。
- **第四步**：如果复购/推荐率高，再找小厂代工 PCB 和外壳。

### 5. 避坑清单

- **别做彩色 e-ink**：成本翻 3 倍，刷新慢，没必要。
- **别做触摸屏**：冰箱贴不需要交互，手机才是输入端。
- **别做 App**：做网页，iOS/Android 通吃，省审核时间。
- **别囤货**：e-ink 屏有批次差异，先小批量测试。
- **别忽视磁吸**：冰箱门弧度不同，用强磁 + 硅胶垫，否则会掉。

### 6. 如果只想"玩"不想"卖"

- **直接买现成**：淘宝搜"电子墨水屏 冰箱贴"，已有成品约 ¥200–400。
- **自己 DIY**：按上面清单买件，周末 2 天能搞定，总花费 ¥200 以内。
- **代码**：直接 clone 作者仓库，改 `config.h` 里的 WiFi 和 API 地址。

# 项目分析：Scissor.studio

## 一、它怎么赚钱？

先泼冷水：**"Free alternative" 本身就是最危险的商业模式信号。** 一个免费工具要活下来，只有几条路：

- **Freemium 订阅**：免费版限制导出分辨率、去水印、模板数量、商用授权；Pro 版按月/年收费。这是设计工具最主流的路径（Canva 就是靠这个做到几百亿美金）。
- **API / 白标授权**：把底层能力打包卖给 SaaS 公司、电商后台、营销平台，按调用量或席位收费。B 端比 C 端好收钱。
- **模板 / 素材市场抽成**：设计师上传模板，平台抽 20%-30%，用户为"好看的成品"付费，而不是为"工具"付费。
- **流量变现（最弱）**：广告、联盟营销、导流到付费设计服务。免费工具靠这个基本养不活团队。
- **企业版**：团队协作、品牌资产管理、SSO、权限控制、审计日志——这些才是企业愿意掏钱的地方。

**毒辣判断**：如果它现在只有"免费"没有清晰的付费墙设计，那它要么在烧融资换增长，要么就是个个人项目/引流工具。你模仿前先想清楚——**你打算在哪一刀切下去收费？**

---

## 二、普通人如何低成本模仿？

核心思路：**不要做"全能设计工具"，做"某个垂直场景的 10 秒出图工具"。** 全能工具你打不过 Canva，但"小红书封面生成器""闲鱼商品图生成器""公众号头图生成器"你能做。

### 可执行步骤

- **第 2 步：技术栈选最省力的**
  - 前端：Next.js / Vite + React，直接部署 Vercel 免费额度。
  - 画布：Fabric.js 或 Konva.js（开源，能拖拽、文字、图片、导出）。
  - 模板：先用 Figma 设计好，导出 JSON 配置，不要自己从零写渲染引擎。
  - 后端：Supabase（免费额度够早期用）做用户、存储、支付记录。

- **第 3 步：MVP 只做三件事**
  - 选模板 → 改文字/换图 → 导出高清图。
  - 其他功能（协作、图层、滤镜、AI 生成）全部砍掉。

  - 不要投广告，早期投广告等于烧钱验证一个没验证的产品。

- **第 5 步：收费设计（从第一天就埋）**
  - 免费：带水印、低分辨率、每天 3 次。
  - 付费：9.9 元/月 去水印 + 高清 + 商用授权。
  - 企业：99 元/月 团队模板库 + 品牌色 + 批量导出。
  - **关键**：付费点要放在"用户已经做出满意作品、准备导出"的那一刻，转化率最高。

- 不要免费到底——免费换来的用户不会付费，只会提需求。
