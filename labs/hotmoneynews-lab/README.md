# 项目分析：SCM（macOS 本地 AI 照片/视频搜索）

先给结论：**这是一个典型的"技术炫技型开源项目"，不是生意。** 它解决的是"我本地有一堆照片视频，想用自然语言搜"这个需求——但这个需求本身付费意愿极低，因为苹果 Photos、Google Photos、甚至 Spotlight 已经在免费做这件事。下面拆开讲。

---

## 一、它怎么赚钱？（残酷版）

**直接答案：靠这个项目本身，几乎赚不到钱。** 但可以拆出几条勉强能走的路：

- **卖"本地隐私"这个点给特定人群**：律师、医生、记者、企业合规部门——他们不能把素材传到云端。做成一次性买断的 macOS App（$29–$79），走 Gumroad / Setapp 分发。这是唯一有真实付费逻辑的路径。
- **开源引流 + 卖 Pro 版**：核心开源，Pro 版加批量处理、多机同步、团队共享索引、CLI 自动化。参考 Raycast、Obsidian 的模式。
- **卖"索引引擎"给 B 端**：把 embedding + 向量检索的本地化能力打包成 SDK，卖给做数字资产管理（DAM）、影视后期素材库的公司。这才是钱多的地方，但需要销售团队。
- **别做的**：订阅制 SaaS、面向 C 端大众、靠 GitHub star 融资。这三条都是死路。

**判断标准**：如果 3 个月内没有 10 个愿意付 $50 以上的用户，就砍掉，当作品集项目。

---

## 二、普通人如何低成本模仿？

核心思路：**别重造轮子，把现成的开源组件拼起来，2 周内出 MVP。**

### 技术栈（全部免费/开源）

- **模型层**：直接用 `CLIP`（OpenAI 开源）或 `SigLIP`（Google，效果更好），做图文跨模态 embedding。视频按帧抽，每 N 秒一帧。
- **向量库**：本地用 `FAISS` 或 `ChromaDB`，别上 Pinecone，省成本。
- **抽帧**：`ffmpeg` 一行命令搞定，别自己写解码。
- **UI**：macOS 用 SwiftUI + Python 后端（`PyInstaller` 打包），或者干脆先做 CLI + 一个简单 Web UI（`Gradio`，半天出原型）。
- **索引存储**：SQLite 存元数据 + FAISS 存向量，够用。

### 执行步骤（按顺序）

1. **第 1 天**：跑通最小闭环——给一张图，用 CLIP 生成向量，存进 FAISS，再用文字 query 搜出来。
2. **第 2–3 天**：接入 `ffmpeg` 抽帧，把视频也塞进同一个索引。
3. **第 4–5 天**：写个 `Gradio` 界面，输入框 + 结果缩略图网格。能 demo 就行。
4. **第 6–7 天**：处理性能——增量索引（只处理新文件）、后台线程、缓存。这步决定用户会不会骂你。
5. **第 2 周**：打包成 macOS App（`py2app` 或 `Briefcase`），发到 GitHub + Product Hunt。

### 差异化建议（否则你就是第 100 个克隆）

- **只做视频**：照片搜索已经被苹果做烂了，视频帧搜索还是蓝海。
- **只做某个垂直场景**：比如"给剪辑师找 B-roll"、"给播客主找封面素材"。
- **加时间轴搜索**："找出所有出现红色汽车且时长超过 3 秒的片段"——这是通用工具做不到的。

### 成本估算

- 开发时间：2 周（业余）
- 现金成本：$0（全开源）+ $99/年 Apple 开发者账号（如果要上架）
- 算力：本地跑，用户自己的机器，你零成本

## 三、一句话总结

**这个项目作为技术 demo 合格，作为生意不合格。** 想模仿就把它当练手项目，2 周做出 MVP，然后立刻去找那 10 个愿意付钱的律师或剪辑师——找不到就换方向，别恋战。
