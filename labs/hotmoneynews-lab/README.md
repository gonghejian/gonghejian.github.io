#### 分析（毒辣创业教练）

# 项目分析：Capsule

## 一、这是什么

Capsule 的核心卖点：**一个单文件 Web App，数据直接存进 SQLite 文件里**。用户下载一个文件（或一个可执行包），双击运行，浏览器打开，数据落地在本地 SQLite，不需要服务器、不需要云数据库、不需要 Docker。

它踩中的痛点很明确：
- 传统 Web App 要部署、要运维、要买数据库
- 桌面 App 要打包、要签名、要跨平台适配
- 用户对"数据存在别人服务器上"越来越敏感

Capsule 的定位是：**给开发者一个"把 Web App 变成可分发单文件"的运行时**，数据主权归用户。

---

## 二、它怎么赚钱？

从产品形态和 HN 这类项目的常见路径看，变现逻辑大概率是：

- **开源核心 + 商业授权**：单文件运行时开源，但企业内部分发、白标、SaaS 化封装需要商业 license
- **托管/同步服务**：本地 SQLite 很好，但"多设备同步"是刚需。官方提供加密同步层，按月订阅
- **模板/应用市场抽成**：开发者用 Capsule 做出来的 App 上架市场，平台抽 15%–30%
- **企业版**：SSO、审计日志、集中分发、合规打包，按席位收费
- **技术支持与定制**：帮企业把内部工具 Capsule 化，按项目收费

**关键判断**：单靠"单文件运行时"本身很难直接收钱，因为技术门槛不高、容易被 fork。真正的护城河在**同步服务 + 生态市场 + 企业合规**这三层。

---

## 三、普通人如何低成本模仿？

### 技术路线（最小可行版）

- **选一个能打包的运行时**：Bun 的 `bun build --compile` 或 Node 的 `pkg`/`nexe`，把 HTTP 服务 + 静态前端 + SQLite 驱动打成一个可执行文件
- **数据库用 SQLite**：`better-sqlite3` 或 Bun 内置 `bun:sqlite`，零配置，文件即数据库
- **前端用单页应用**：Vite + React/Svelte，构建产物内嵌进二进制
- **启动逻辑**：程序启动 → 起本地 HTTP 服务（随机端口）→ 自动打开浏览器 → 数据写入同目录 `.db` 文件
- **跨平台**：分别编译 macOS / Windows / Linux 三个二进制，用 GitHub Actions 自动出包

### 低成本执行清单

- **第一周**：做一个"个人书签管理器"或"本地记账本"作为 demo，验证单文件打包 + SQLite 读写 + 浏览器自动打开这条链路
- **第二周**：抽象出通用运行时，把 demo 的业务代码抽掉，留下 `app/` 目录让用户塞自己的前端
- **第三周**：写一份 5 分钟上手文档，录一个 2 分钟演示视频，发 HN / Reddit / V2EX
- **第四周**：加"导出/导入 SQLite 文件"和"加密备份"两个功能，这是用户最关心的数据安全感
- **获客**：在 HN 发 Show HN，标题格式照抄："Show HN: X – Single-file web apps that save data into SQLite"
- **变现起点**：先免费开源攒 star，等有 500+ star 再推"加密同步"付费层，定价 $5–10/月

### 避坑提醒

- **不要一上来做同步**：同步是分布式系统地狱，先做单机，验证需求
- **不要做应用市场**：冷启动阶段没开发者愿意来，先自己做一个杀手级 demo
- **注意杀毒软件误报**：打包成 exe 容易被 Windows Defender 拦，提前做代码签名或提供 zip 分发
- **macOS 公证**：不公证的话用户打不开，花 $99/年买 Apple Developer 账号
- **别碰"替代 Electron"的叙事**：那个赛道太挤，聚焦"数据主权 + 零运维"这个差异点

---

## 四、一句话总结

Capsule 的本质是**把"部署"这件事从 Web App 里删掉**，让数据回到用户硬盘。普通人模仿的技术门槛不高，真正的难点在**分发体验和同步服务**。先做一个能跑的单文件 demo 发出去，比想清楚商业模式更重要。

# 项目分析：In-Flight Simulator（你只是乘客的"飞行模拟器"）

这是一个典型的 **HN 式玩笑项目**——把"飞行模拟器"这个硬核品类反转成"你只是个乘客，什么都不能做"。笑点在于：模拟的不是开飞机，而是坐飞机时那种无聊、被困、被动等待的体验。

---

## 1. 它怎么赚钱？

**先说结论：大概率不赚钱，也不打算赚钱。** 这类项目本质是"作品集/病毒传播工具"，变现路径极其有限。但如果硬要拆，可能的路径：

- **广告/赞助位**：页面停留时间长（模拟飞行几小时），可嵌入航司、旅行保险、降噪耳机、颈枕等广告。但流量不稳定，CPM 极低。

> 一句话：**它的"钱"是注意力和简历，不是现金流。**

---

## 2. 普通人如何低成本模仿？

核心公式：**一个大家都熟悉的"高参与度场景" + 剥夺参与感 + 还原无聊细节 = 病毒式讽刺作品。**

### 可执行步骤

- **选场景**：挑一个"通常需要你操作/参与，但现实中你只能干等"的场景。例如：
  - 医院候诊模拟器（你只能坐着刷手机）
  - 驾照路考模拟器（你只是后座乘客）
  - 电梯模拟器（你按了楼层，然后站着）
  - 会议模拟器（你只是旁听，不能发言）
  - 机场安检排队模拟器

- **技术栈**：纯前端即可，零后端成本。
  - HTML + CSS + 少量 JS（`setInterval` 做计时器）
  - 用 CSS 动画/渐变模拟窗外云层、机舱灯光
  - 音效用免费素材（引擎白噪音、广播提示音）
  - 部署到 Vercel / Netlify / GitHub Pages，**0 元**

- **还原"无聊的真实感"**（这是笑点来源）：
  - 随机广播："本次航班预计延误 40 分钟"
  - 邻座乘客偶尔碰你胳膊
  - 安全带指示灯反复亮灭
  - 进度条极慢，且不能加速
  - 唯一交互按钮："呼叫乘务员"（点了没反应）

- **传播设计**：
  - 标题用 HN 体："I made X, except you're just Y"
  - 加一个"分享你被困了多久"的截图按钮
  - 发到 HN / Reddit r/InternetIsBeautiful / 小红书"摸鱼神器"

- **成本控制**：
  - 总工时 1–2 天，不写后端，不接支付
  - 不做 App，只做网页（移动端适配即可）
  - 用现成字体和 emoji，不买素材

### 关键提醒

- **别想着赚钱**，想着"被看到"。这类项目的 ROI 在曝光，不在收入。
- **笑点必须精准**：模仿对象要足够普遍，剥夺感要足够真实，否则变成无聊的静态页面。
- **可复制性极高**：今天做"乘客模拟器"，明天就能做"乘客模拟器 2：转机版"。

---

**总结**：这是一个用幽默换流量的作品，不是生意。想模仿，就复制它的**结构**（熟悉场景 + 被动体验 + 细节还原），而不是复制它的**主题**。
