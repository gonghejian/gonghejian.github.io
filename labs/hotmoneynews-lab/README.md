# 项目分析：pcdealcheck.com

## 一、它怎么赚钱？

先泼冷水：这类"比价工具"本身几乎没有护城河，赚钱路径窄且脆弱。可能的变现方式：

- **联盟营销（Affiliate）**：最现实的一条。把每个零件链接到 Amazon / Newegg / 京东等，靠成交抽佣。这是这类站点的标准打法，但转化率低，用户看完价格往往自己去别处下单。
- **导流到整机/二手交易平台**：把"这台整机值不值"的结论导流给回收商或整机卖家，收线索费。
- **广告位**：流量起来后挂 Google AdSense 或硬件品牌广告，单价低，需要大流量才够看。
- **付费 API / B 端授权**：给二手交易平台、回收商提供"整机拆解估价"能力，按调用收费。这是唯一有点想象力的方向，但需要数据质量和稳定性支撑。
- **数据订阅**：给黄牛/倒卖党提供"低于拆件价"的整机监控推送，收订阅费。灰色但真实存在需求。

**残酷现实**：这个项目当前形态（一个 Show HN 小工具）大概率还没赚钱，靠的是 HN 流量做验证。真正的钱在"数据源稳定性"和"交易闭环"上，而不是比价页面本身。

---

## 二、普通人如何低成本模仿？

核心洞察：**这个项目的本质不是"比价"，是"把非标商品拆解成标准件再定价"**。这个模式可以平移到很多品类。以下是可执行路径：

### 第一步：选一个"整机 vs 拆件"价差明显的品类
- 不要做 PC，红海且数据源难搞（京东/淘宝反爬严）。
- 选：**二手相机套机、乐器套装、自行车整车、显卡矿机、办公家具套装、乐高套装拆卖**。
- 判断标准：整机二手价 < 各零件二手价之和 × 0.85，存在套利空间才有工具价值。

### 第二步：用最低成本搭数据层
- **不要自建爬虫**（法律和运维成本高）。先用**人工 + 表格**跑通 100 个样本，验证"拆件价 > 整机价"的比例。
- 数据源优先用**有开放 API 或结构清晰的平台**：eBay（有 API）、闲鱼（无 API，用人工抽样）、BrickLink（乐高，有 API）。
- 用 Google Sheets + IMPORTHTML / Apps Script 做半自动抓取，零服务器成本。

### 第三步：MVP 用最土的方式做
- 一个静态页面（Vercel/Cloudflare Pages 免费）+ 一个输入框（粘贴整机链接或手动填零件）。
- 后端用 **Google Sheets 当数据库**，Cloudflare Worker 做轻量 API。总成本 < 5 美元/月。
- 先不做自动识别，让用户**手动勾选零件**，你返回"拆件总价 vs 整机价"对比。人工可接受就先别上 AI。

### 第四步：验证再投入
- 发到对应品类的 Reddit / 贴吧 / 小红书，看有没有人真的用。
- 关键指标：**用户是否在看完结果后点击了你的联盟链接**。点击率 < 2% 就说明工具没解决真痛点，别加功能，换品类。

### 第五步：变现从第一天就埋
- 每个零件价格旁直接挂联盟链接，别等流量。
- 加一个"降价监控"邮件订阅，收集邮箱，后续做付费推送。

### 避坑清单
- **别碰反爬严重的平台**，数据断供工具就死。
- **别做"全品类"**，一个品类做透比十个品类半吊子强。
- **别高估 AI 识别**，OCR/图像识别整机配置的准确率在真实场景下很低，人工兜底更靠谱。
- **法律红线**：爬取用户生成内容（如闲鱼商品描述）用于商业用途有风险，优先用官方 API 或公开结构化数据。

---

**一句话总结**：这个项目的可复制内核是"非标品拆解定价"的方法论，而不是 PC 比价本身。低成本模仿的关键是——选对品类、用表格和静态页跑通闭环、第一天就埋变现、用点击率而非访问量做生死判断。

  - 付费版：多仓库托管、团队协作、历史版本对比、私有部署
  - 定价参考：$9–19/人/月，卖给中小团队

  - Show HN 上榜 → 个人品牌 → 接咨询/外包/招聘
  - 这是很多开源作者的**真实变现方式**，产品只是名片

## 二、普通人如何低成本模仿？

### 技术侧（1–2 周可出 MVP）

- **选一个垂直语言/生态**：别做"任意仓库"，做 Go / Rust / Python 里**一个**，做深做透，避开正面竞争
- **复用现成解析器**：Go 用 `go/ast` + `go/packages`，Python 用 `ast`，别自己写 parser
- **前端用现成图库**：Cytoscape.js / D3 / vis-network，别造轮子
- **输出形态先做静态 HTML**：单文件、可离线、可分享，比做 Web 服务成本低 10 倍
- **部署零成本**：GitHub Pages + GitHub Actions 自动生成，白嫖到底

### 产品侧（差异化是活路）

- **选一个别人没做的视角**：
  - 只画"包依赖 + 循环依赖"（架构腐化检测）
  - 只画"HTTP 路由 → handler → service"调用链
  - 只画"谁调用了这个废弃函数"（重构辅助）
- **加一个"钩子功能"**：比如"一键找出循环依赖并给出拆分建议"，这是付费点
- **做 CLI 优先**：`npx codemap .` 一行命令出图，降低试用门槛

### 增长侧（低成本获客）

- **Show HN / Reddit r/golang / V2EX** 首发，标题写清"解决什么痛点"
- **写一篇对比文**："我用 3 个工具画 Go 依赖图，只有这个能跑通大仓库"
- **在 GitHub 上给热门 Go 项目提 PR**，附上生成的架构图，自然引流
- **做 SEO 长尾**："golang dependency graph visualization" 这类词竞争小

### 变现侧（先别急）

- **前 3 个月只做用户，不做收费**
- **收集邮箱**，做"团队版 waitlist"
- **等有 500+ star 再谈付费**，否则定价没人理

# Uncracked City 项目分析

## 一、它怎么赚钱？

**核心判断：这是一个典型的"技术Demo型产品"，当前大概率不赚钱，赚钱路径靠后置。**

- **现状**：Show HN 上的项目多为个人作品/技术验证，Uncracked City 本质是"用 LLM 扮演会说谎的嫌疑人"的侦探推理游戏，卖点是 AI 交互体验，不是成熟商业产品。
- **可能的变现路径**（按可行性排序）：
  - **订阅制/内购**：免费玩前 1-2 个案件，后续案件/章节付费解锁（类似解谜游戏的通行做法）。
  - **案件包 DLC**：定期上新剧本，按包售卖，维持复购。
  - **API/引擎授权**：把"LLM 说谎嫌疑人对话引擎"打包成 SDK，卖给其他游戏开发者或剧本杀/密室行业做 AI 主持人。
  - **广告/流量变现**：免费 + 广告，适合早期拉用户，但会破坏沉浸感，慎用。
  - **B 端定制**：给品牌做营销互动小游戏（如"找出内鬼"式品牌活动）。
- **关键风险**：LLM 推理成本随对话轮次线性上升，免费用户越多亏得越多，必须设计"对话轮次上限"或"缓存常见问答"来控制成本。

## 二、普通人如何低成本模仿？

**核心思路：不自己训模型，用现成 API + 轻量前端，把"说谎的嫌疑人"做成可复用的对话框架。**

- **技术栈（最低成本组合）**
  - 前端：Next.js / Vite + React，或直接用 Vercel 部署静态页。
  - LLM：用 DeepSeek / 通义千问 / GLM 等国产 API（比 OpenAI 便宜一个数量级），或本地跑小模型（Ollama + Qwen 7B）零 API 成本。
  - 后端：Serverless 函数（Vercel/Cloudflare Workers）转发请求，隐藏 API Key。
  - 存储：SQLite / Supabase 免费层存案件剧本和对话记录。

- **"说谎嫌疑人"的实现技巧（这是产品灵魂，成本极低）**
  - 每个嫌疑人写一段 **System Prompt**：设定身份、秘密、谎言规则（"你隐瞒了 X，被问到 X 时给出看似合理的假答案，但细节前后矛盾"）。
  - 用 **结构化剧本**（JSON）定义：真相、每个嫌疑人的谎言点、可被戳穿的矛盾点。
  - 加一个 **"矛盾检测"轻逻辑**：当玩家指出前后矛盾时，触发嫌疑人"慌张/改口"的预设回复，制造推理爽感——不需要复杂 AI，规则 + LLM 混合即可。

- **内容生产（最大成本项，用巧劲）**
  - 先做 **3 个高质量案件**验证体验，别贪多。
  - 剧本用 AI 辅助生成初稿 + 人工打磨矛盾点，一个人一周能出 1 个案件。
  - 参考现成剧本杀/推理小说结构，降低原创门槛。

- **成本控制**
  - 限制每局对话轮次（如 30 轮），超出提示"证据不足"。
  - 对高频问题做缓存/预设回复，减少 API 调用。
  - 用国产模型 + 免费额度起步，日活 <100 时月成本可控制在几十元内。

- **冷启动**
  - 先发 Show HN / 小红书 / B 站"AI 侦探游戏"话题，用"嫌疑人会撒谎"做钩子。
  - 收集玩家最常问的问题，反哺剧本优化。

- **可执行的第一步（本周就能做）**
  1. 选 1 个简单案件（3 嫌疑人、1 凶手），手写 JSON 剧本。
  2. 用 DeepSeek API + 一个聊天界面，跑通"问嫌疑人 → 得到带谎言的回答"。
  3. 部署到 Vercel，发一条帖子测试反馈，再决定是否加案件和付费墙。

**一句话总结**：这项目的护城河不在技术（LLM 对话谁都能做），而在**剧本质量和"说谎逻辑"的设计**——普通人模仿的正确姿势是"轻技术 + 重剧本 + 严控 API 成本"，先用 3 个案件验证有没有人愿意玩，再谈赚钱。

  - **个人品牌变现**：作者靠这个项目接咨询、找工作、涨粉，间接变现。**这才是真实收益。**
