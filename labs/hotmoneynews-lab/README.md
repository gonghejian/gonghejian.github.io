# 项目分析：PS2 游戏静态重编译到 WebAssembly

## 一、它怎么赚钱？

先说结论：**这个项目本身几乎不赚钱，但它踩中的赛道可以赚钱。** 直接卖"PS2 游戏跑在浏览器里"是死路，原因如下：

- **法律雷区**：PS2 游戏 ROM 和 BIOS 的版权归属索尼和各家发行商，静态重编译不改变版权归属。你分发重编译产物 = 分发盗版游戏。
- **技术受众极窄**：会为"在浏览器里跑 PS2 游戏"付费的人，基本都自己会折腾模拟器。
- **性能天花板**：WASM 跑 PS2 级别的 3D 游戏，体验远不如原生 PCSX2。

**真正能变现的路径（按可行性排序）：**

- **技术授权 / 咨询**：静态重编译（static recompilation）是当前游戏保存（game preservation）和复古移植领域的热点。把技术卖给想把自己的老游戏移植到现代平台的**版权方**（发行商、独立开发者）。这是最干净的商业模式——你只处理他们拥有版权的游戏。
- **SaaS 工具链**：做一个"上传你的 ROM → 自动重编译 → 输出可发布的 WASM 包"的平台，按项目收费。客户是**拥有版权的开发者**，不是玩家。
- **复古游戏发行平台**：和版权方合作，做"官方授权的浏览器复古游戏库"，类似 GOG 但跑在浏览器里。抽成或订阅制。
- **内容 / 教程变现**：静态重编译是硬核技术，做付费课程、付费 Newsletter、接企业内训。受众是逆向工程爱好者和游戏开发者。
- **开源引流 + 赞助**：GitHub Sponsors、Patreon，靠技术声誉接私活。收入不稳定但门槛低。

**一句话**：赚钱的不是"PS2 游戏上网页"，而是"静态重编译这套技术能力"。

## 二、普通人如何低成本模仿？

先泼冷水：**"普通人"如果指没有逆向工程和编译器背景的人，这个项目你模仿不了。** 静态重编译需要懂 MIPS 汇编、ELF 格式、WASM 工具链、图形 API 映射。但你可以**降维模仿**，从更简单的目标切入：

### 技术降维路线（按难度从低到高）

- **从更老的平台开始**：NES / Game Boy / SNES 的静态重编译项目已有先例（如 `NES-recomp`、`gb-recomp`），指令集简单，社区资料多。先跑通一个 GB 游戏的重编译，再往上爬。
- **用现成工具链**：不要从零写。研究 `retdec`、`Ghidra`、`Binary Ninja` 的反编译输出，配合 `Emscripten` 做 WASM 后端。你的工作是"胶水"，不是"造轮子"。
- **只做 Demo 级别**：选一个**开源 / 免费授权**的老游戏（如 id Software 早期作品、Homebrew 游戏），重编译到 WASM，做成技术 Demo。目的是展示能力，不是分发游戏。
- **聚焦一个垂直场景**：比如"把某类老游戏引擎重编译到 Web"，做深不做广。深度比广度值钱。

### 低成本执行清单

- **第 1 周**：克隆 `ps2-web-recomp`，跑通它的构建流程，理解它做了什么、没做什么。读它的 issue 和 README。
- **第 2 周**：找一个更简单的开源重编译项目（搜 `static recompilation wasm`），对比架构差异。
- **第 3-4 周**：选一个**你有权处理的**老游戏或自制游戏，尝试重编译。目标不是完美运行，是"能跑起来一个画面"。
- **第 2 个月**：把过程写成技术博客 / 视频，发到 HN、Reddit r/emulation、Twitter。这是你唯一的"获客"渠道。
- **第 3 个月**：如果做出东西，去联系**独立游戏开发者**，问他们有没有老游戏想移植到 Web。免费做 1-2 个案例，换推荐信和作品集。

### 避坑清单

- **不要分发商业游戏 ROM**：这是法律红线，HN 上这类项目被下架是常态。
- **不要指望这个项目直接变现**：把它当"技术名片"，不是"产品"。
- **不要单打独斗**：加入 emulation / reverse engineering 社区（Discord、Reddit），信息差就是你的优势。
- **不要追求 100% 兼容**：静态重编译的卖点是"特定游戏完美运行"，不是"通用模拟器"。
